# 设计说明

简体中文 · [English](DESIGN.md)

## 设计目的

图像提示词反推本质上是一个逆问题：用户提供最终成片，系统需要仅从像素中推断出一组有效的生成约束。不同提示词和模型参数可能得到相似画面，而“描述得像”也不等于“能够复现”。

这个 skill 的设计目的，是把模糊的逆向猜测转化为更可控的流程：把图像拆成可观察约束，按照视觉影响排序，再通过足够小的修改逐轮诊断和收敛。

## 重点解决的问题

### 1. 图片描述不等于图片复刻

普通图片描述只需要说明“画了什么”。复刻提示词还需要表达空间关系、裁切、透视、主体尺度、光线方向、明暗层级、材质反应和渲染方式。

因此，skill 会把图像视为一组物理构成，而不是进行故事化或文学化解读。

### 2. 不同差异的影响并不相等

当镜头角度或主体轮廓错误时，微小纹理是否一致几乎不重要。没有优先级的分析会浪费提示词空间，也让纠错变得不稳定。

默认优先级是：

1. 空间布局与轮廓；
2. 镜头与透视；
3. 主体比例、姿势和相互关系；
4. 光照与明暗层级；
5. 色彩处理；
6. 材质与渲染方式；
7. 微观细节。

如果用户明确指出最在意的部分，该部分会覆盖默认顺序，成为最高优先级锚点。

### 3. 不断追加提示词会破坏因果关系

每次失败后继续追加形容词，容易造成互相冲突的约束，也无法判断究竟是哪项修改带来了改善或退化。

纠错模式会先对可见差异排序，每轮只修改影响最大的一个到三个原因，已经有效的描述保持稳定。

### 4. 风格与内容经常被混在一起

可迁移风格应该描述画面的处理方式，而不是参考图中的人物、服装、姿势、道具、场景或物体颜色。一旦混入内容，风格提示词就很难用于新主体。

因此，风格提取模式设置了明确的纳入与排除边界。除非某个具体颜色本身构成核心风格，否则只表达低饱和、冷暖统一、高对比等抽象色彩处理。

### 5. 纯文字提示词存在真实的控制上限

精确身份、文字、姿势、深度、边缘和几何可能无法仅靠文字稳定控制。提示词变长并不等于控制能力变强。

当迭代停滞时，skill 会建议最小必要升级：固定模型和种子、匹配画幅、使用参考图、姿势/深度/边缘控制、局部重绘或直接合成。

## 架构设计

skill 采用渐进式披露结构：

- `SKILL.md` 负责模式路由、共同约束和迭代纪律。
- `references/workflows.md` 保存三种模式的详细流程与输出规范。
- `agents/openai.yaml` 提供用户可见的名称、简介和调用示例。

仓库说明、自动校验和 Release 文件都位于可安装 skill 目录之外，避免无关内容占用运行时上下文。

## 三种模式

### 复刻反推

把一张参考图转换为结构化英文提示词。顺序依次为最高优先级视觉锚点、主体几何、构图、镜头、光线、色彩、材质、渲染与防漂移约束。负面提示词不是必选项，只在确实能够防止常见错误时使用。

### 双图纠错

直接比较原图与生成图。每个重要差异都按照下面的因果链进行判断：

```text
原图证据 → 生成图偏差 → 可能的提示词原因 → 最小修正
```

输出包括按影响排序的差异、简洁修改策略和完整优化提示词。

### 风格提取

风格提取采用严格输出契约：只输出两到三句简洁中文，不加标题、列表、分析过程或解释。这样既能直接复制，也能降低内容泄漏到风格提示词中的概率。

## 设计原则

- **感知相似度优先于词汇密度。** 提示词更长不代表控制更强。
- **可观察证据优先于自信猜测。** 不确定的镜头、媒介和渲染器判断必须标注不确定性。
- **保持稳定约束，避免全量重写。** 已经有效的描述会保留到下一轮。
- **默认与工具无关。** 默认使用中性的英文提示词结构；只有明确生图工具后才加入专用权重或参数。
- **严格区分内容与风格。** 风格模式不会默默保留参考图场景内容。
- **诚实说明能力边界。** 不承诺纯文字提示词能够确定性地实现像素级复刻。

## 非目标

这个项目不会：

- 自行生成图片；
- 保证不同模型或不同运行结果完全一致；
- 把不可见的相机元数据伪装成确定事实；
- 取代图生图、结构控制、局部编辑或合成；
- 授予复制受保护、私密或未获授权图片的权利；
- 把某一家生图工具的提示词语法当作统一标准。

## 成功标准

满足以下条件时，说明 skill 按预期工作：

- 输出提示词能够直接复制，且内部没有冲突；
- 用户最在意的视觉特征被明确保留；
- 纠错只提出少量高影响修改；
- 已经成功的约束在多轮迭代中保持稳定；
- 风格提示词可以应用到新主体，而不会带入原参考图的场景内容；
- 当其他控制方式更合适时，停止无意义地扩充文字提示词。
